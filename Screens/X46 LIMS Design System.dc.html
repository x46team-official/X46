Enterprise Laboratory Information Management System — Design System

Design Principles

1. Clarity Over Decoration

Clean, focused interfaces that prioritize information hierarchy and legibility over visual flourish.

2. Consistency Over Customization

Reusable components and patterns across all screens ensure predictable interactions and reduce cognitive load.

3. Data First

Enterprise data visibility and scannability are prioritized. Tables, reports, and results are the core UI.

4. Predictable Interactions

Actions, feedback, and workflows follow consistent patterns across the application.

5. Clear System Feedback

Every action receives visible feedback: loading, success, error, or validation. Users always know the system state.

6. Efficient Workflows

Forms, navigation, and workflows are designed for fast, accurate data entry and retrieval.

7. Accessibility by Default

Keyboard navigation, sufficient contrast, and semantic HTML are built into every component.

8. Trust Through Transparency

Clinical accuracy, audit trails, and clear error messaging build user confidence in the system.

Accessibility & Responsive Rules

Accessibility Requirements

  • Keyboard navigation: All interactive elements accessible via Tab key
  • Visible focus states: 3px outline in primary color on focused elements
  • Color contrast: Text contrast ratio ≥ 4.5:1 (WCAG AA)
  • Labels: Every form input has associated label element
  • Required fields: Marked with asterisk AND aria-required
  • Error messages: Associated with inputs via aria-describedby
  • Status indication: Not by color alone. Use icons, text, and badges
  • Touch targets: Minimum 44px × 44px for interactive elements

Using This Design System

For Designers

  • Use component naming convention
  • Apply tokens (colors, spacing, typography)
  • Document new components here
  • Maintain consistency across all screens

For Developers

  • Use CSS custom properties (--color-*, --space-*)
  • Build components with states (hover, focus, disabled)
  • Follow accessibility guidelines
  • Test responsive behavior at breakpoints

General Rules

  • No custom colors outside this system
  • Use spacing scale exclusively
  • Reuse components; never duplicate
  • Update this system; don't create exceptions
